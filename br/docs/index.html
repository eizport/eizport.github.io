Documentação

Documentação do Eizport

Como a tela Exportar funciona, o que vai em cada formato de arquivo, como a importação põe tudo de volta no lugar, e como controlar tudo pelo código.

Primeiros passos

  • Introdução

    O que o Eizport faz, como ele se encaixa na exportação e na importação do próprio WordPress e para onde ir em seguida.

  • Instalação

    Instale o plugin pelo diretório de plugins do WordPress.org, confira os requisitos e adicione o Importador do WordPress para importar.

  • Sua primeira exportação

    Exporte uma página com sua mídia e a configuração de página inicial em menos de um minuto.

  • Importação

    Como um pacote é importado com o Importador do WordPress, o que acontece com a mídia, os arquivos de conteúdo e as opções, e as outras formas de importar.

  • Multisite

    O Eizport numa rede WordPress: ativação na rede ou por site, quem pode o quê, onde ficam os arquivos de cada site, WP-CLI com --url e desinstalação.

Casos de uso

  • Menus do cabeçalho para o staging

    Um site montado localmente — páginas, um menu de cabeçalho com submenus e a posição dele no tema — repetido no staging sem refazer o menu à mão.

  • Aparência do tema para o staging

    Uma mudança na aparência de um tema feita localmente — a última regra CSS, o logo, um widget, ou a paleta de um tema de blocos — levada para o staging sem mexer no que o staging tem de próprio.

  • Cabeçalho do site para o staging

    O cabeçalho de um tema de blocos refeito localmente no editor do site — um layout novo, a navegação dele, uma imagem — e um modelo de página, levados para o staging no lugar dos que o staging tem, sem um Cabeçalho 2.

  • Galerias para o staging

    Páginas feitas com blocos Imagem, Galeria e Capa, levadas para um site onde as mídias ganham outros IDs — e ainda editáveis como estavam.

  • Links internos para o staging

    Páginas que apontam umas para as outras, para produtos e para categorias, montadas localmente e levadas para o staging — com todo link apontando para o staging, não de volta para o site local.

  • Categorias de produto para o staging

    Os produtos de uma loja levados com as categorias como estão — descrições, categorias ascendentes e miniaturas — e não só com os nomes delas.

  • Segunda entrega para o staging

    Entregar páginas novas a um staging que já tem as mídias da primeira entrega — sem duplicar as imagens e sem links para o site local.

  • De subsite para subsite

    Numa rede, um site montado num subsite e levado para outro — o publicado, ou uma cópia nova — com as mídias, os links e as configurações apontando para o site certo.

  • Demonstração para o cliente no Playground

    Uma página nova mostrada a um cliente no WordPress Playground: um link que abre direto nessa página, com os plugins do site como estão.

  • Playground no seu idioma

    A demonstração de um site em inglês mostrada em português no WordPress Playground: o painel, o tema e os plugins traduzidos, num só link.

  • Tipos de post personalizados no Playground

    Um site cujos tipos de post ficam num plugin obrigatório, mostrado no WordPress Playground: o plugin vai no .zip e roda antes da importação.

  • Advanced Custom Fields para o staging

    Receitas feitas com o Advanced Custom Fields (ACF) — o tipo de post, a taxonomia, o grupo de campos e os valores delas — levadas ao staging com cada foto, página e termo apontando certo.

  • Elementor para o staging

    Uma página de destino feita com o Elementor — as imagens dela, um modelo de seção salvo e as cores e fontes globais do site — levada ao staging com o importador do próprio Elementor, tudo apontando para os itens do staging.

Exportação

  • Tela Exportar

    A nova tela Ferramentas → Exportar, parte por parte: as ações do cabeçalho, o painel Detalhes, a lista e os painéis laterais.

  • Escolher itens

    Itens por tipo de conteúdo, escolhidos no painel lateral na hora; sugestões; o filtro Seleção; descendentes, anexos, avaliações e funções.

  • Opções

    Exporte as configurações do site uma a uma, por grupo ou todas de uma vez; configurações vinculadas; o que nunca é exportado; como os IDs são remapeados.

  • Menus

    Menus clássicos com os itens e as posições do tema, e navegações de bloco, numa linha própria; o que é sugerido, o que a importação faz com os menus que o outro site já tem, e os limites.

  • Aparência

    A aparência do site em linhas próprias, item por item: theme mods e regras CSS do Personalizador, grupos de estilo, regras CSS, modelos e partes de modelo do editor do site, e widgets — com uma prévia de cada um, as mídias que eles usam e como o outro site os recebe.

  • Advanced Custom Fields

    O Advanced Custom Fields (ACF) numa linha própria: os tipos de post, taxonomias e grupos de campos dele no formato de exportação do próprio ACF, importados antes do conteúdo, e os campos que guardam IDs apontando para os itens do outro site.

  • Elementor

    O Elementor com o exportador e o importador dele: as configurações do site (o Kit) e os modelos numa linha própria, o design de cada página num arquivo .json, e na importação cada imagem, modelo e link apontando para os itens do outro site.

  • Mídia

    Quais anexos vêm com os itens exportados, como os arquivos de mídia vão dentro dos pacotes e a configuração "Só mídia anexada".

  • Arquivo e formatos

    Escolha entre o WXR simples do WordPress, um pacote .wxrz ou .zip, um .zip do Playground e um plugin que se importa sozinho; nomes de arquivo e o que cada um contém.

  • Como plugin

    Exporte um plugin que importa o próprio pacote: instale-o no outro site, confira o que ele precisa, Executar importação, depois exclua-o.

  • Padrões salvos

    Salve as escolhas da tela Exportar como padrão, por usuário ou para o site inteiro, nas duas telas.

  • Tela clássica

    A tela Ferramentas → Exportar do próprio WordPress com as opções do plugin adicionadas, para quem prefere; também no celular.

Formatos

  • Pacote WXRZ

    O formato .wxrz, entrada por entrada — manifesto, WXR, mídia, post_content e options.json — e as regras de segurança quando um pacote é aberto.

  • Pacote ZIP

    O mesmo pacote como um .zip comum, que qualquer computador abre — como ativá-lo e como ele é lido.

  • .zip do Playground

    Um pacote de blueprint do WordPress Playground que inicia um site com o conteúdo, a mídia, o tema e os plugins exportados — como é montado e como executá-lo.

Configurações

  • Geral

    Configurações do plugin → Geral — se Ferramentas → Exportar é substituída, a tela clássica, os padrões salvos e por quanto tempo as cópias são mantidas.

  • Configurações de exportação

    Configurações do plugin → Exportar — mídia anexada, configurações vinculadas, pacotes .zip e conteúdo como arquivos .html.

  • Cópias

    As exportações guardadas no site — baixar, abrir no Playground, copiar o link, importar, excluir — e como os links delas funcionam.

Desenvolvedores

  • Agentes de IA

    Deixe um agente de IA exportar, importar e gerenciar cópias por você: as habilidades via MCP, o que pedir, o que o agente vê e a segurança embutida.

  • Habilidades

    Cada habilidade eizport/* da Abilities API do WordPress — entrada, saída, permissão — por REST, PHP e MCP.

  • Hooks

    Cada filtro e ação do Eizport, com seus parâmetros e um exemplo.

  • Compatibilidades

    Quais plugins são suportados (WooCommerce, Advanced Custom Fields, Elementor), como o suporte é feito com os hooks públicos e como um plugin traz o seu próprio.

  • WP-CLI

    Exporte e importe pacotes pela linha de comando com wp eizport export e wp eizport import, guarde uma entrega numa pasta para comparar e rode as habilidades com wp eval.
