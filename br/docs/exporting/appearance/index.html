Exportação

Aparência

A aparência do site em linhas próprias, item por item: theme mods e regras CSS do Personalizador, grupos de estilo, regras CSS, modelos e partes de modelo do editor do site, e widgets — com uma prévia de cada um, as mídias que eles usam e como o outro site os recebe.

A aparência do site é exportada em linhas próprias, ao lado dos tipos de conteúdo. Uma linha só aparece quando o tema ativo tem algo nela, e o painel Escolher itens dela lista o que ela tem, cada item com uma prévia:

Linha Cada item Prévia Aparece com
Theme mods do Personalizador Uma configuração de Aparência → Personalizar: Logo, Imagem do cabeçalho, Imagem e cor de fundo, Cor do texto do cabeçalho, as configurações do próprio tema A imagem, a cor ou o valor Um tema com configurações no Personalizador
CSS adicional do Personalizador Uma regra de Personalizar → CSS adicional (um bloco @media conta como uma; um comentário logo antes vai junto) A regra, e qual é: Regra 3 de 3 (a última) Um tema com CSS adicional
Estilos globais do editor Um grupo de Aparência → Editor → Estilos: Paleta de cores, Cores do site, Tipografia, Espaçamento e layout, Elementos, cada bloco com estilos próprios As cores dele, ou um resumo Temas de blocos com estilos salvos
CSS global do editor Uma regra do CSS adicional do editor do site A regra Temas de blocos com CSS adicional ali
Modelos do editor Um modelo do tema ativo editado em Aparência → Editor → Modelos (Páginas, Posts individuais, um personalizado) A marcação de blocos dele Temas de blocos com modelos editados ali
Partes de modelo do editor Uma parte de modelo do tema ativo editada ali: o Cabeçalho, o Rodapé, uma parte própria, com a área dela A marcação de blocos dela Temas de blocos com partes editadas ali
Widgets Um widget — clássico (texto, imagem, menu…) ou de bloco — com a barra lateral dele O texto ou a imagem Temas clássicos com widgets nas barras laterais

Marque uma linha para levar tudo o que ela tem (todo item vem sugerido), ou abra Escolher itens e marque só alguns: a última regra CSS, o logo e a cor de fundo, um widget, o cabeçalho. Elas precisam de um pacote (.wxrz, .zip ou um .zip do Playground): vão no options.json dele — menos os modelos e as partes de modelo, que são posts e vão no WXR como o conteúdo (um .xml simples também os leva).

Só aparece o que foi editado no editor do site: um modelo que está nos arquivos do próprio tema, sem mudanças, o tema do outro site já tem.

O que vai junto

As imagens que os itens escolhidos usam são exportadas com eles, mesmo sem a linha Anexos marcada: o logo, as imagens de cabeçalho e de fundo, as mídias dos widgets de imagem e de bloco, as imagens dos modelos e das partes de modelo, e os uploads para onde os estilos e o CSS apontam (Só mídia anexada, nas configurações de exportação, desliga isso, como no conteúdo).

No outro site

  • As regras CSS (as do Personalizador e as do editor do site) são acrescentadas ao CSS do outro site, como diz Detalhes → Regras CSS na importação: no fim (o padrão), no início, substituindo o bloco de mesmo nome que o outro site já tem (no fim quando não tem nenhum), ou substituindo todo o CSS dele. Elas vão entre dois comentários com o nome do arquivo:

    .deles { color: purple; }

/* head COMB-584 */
.site-footer { background: #ffeedd; }
/* tail COMB-584 */

    O nome é o nome do arquivo sem extensão — aqui COMB-584.wxrz, com o nome de uma tarefa: uma marca de onde as regras vieram. Cada importação acrescenta o próprio bloco — os blocos não são únicos, e o mesmo nome pode aparecer mais de uma vez. Sem os comentários (configurações de exportação, ou o importador), regras que o outro site já tem (mesmo texto) não são repetidas.

  • Quem importa parte da escolha da exportação e pode mudá-la na etapa 1 do importador (CSS adicional), com css_mode/css_markers no eizport/import, ou com --css-mode/--[no-]css-markers no WP-CLI. Ali:

    • Substituir o bloco “COMB-584” que este site já tem — oferecida só quando o CSS do outro site tem um bloco head/tail com o mesmo nome (uma entrega anterior de um arquivo com esse nome): o bloco novo fica no lugar dele, e o resto do CSS fica (replace);
    • Substituir todo o CSS deste site — ficam só as regras do arquivo (replace_all).

  • Os theme mods escolhidos vão para o tema ativo e são mesclados aos dele: o que o arquivo não traz fica (as outras configurações, as posições dos menus). O logo e a imagem do cabeçalho apontam para os anexos importados, e os endereços das imagens de cabeçalho e de fundo para os arquivos importados.

  • Os grupos de estilo escolhidos substituem os mesmos grupos nos estilos do outro site (um tema de blocos); os outros grupos dele ficam.

  • Os modelos e as partes de modelo escolhidos substituem o mesmo modelo do mesmo tema no outro site (mesmo slug: o Cabeçalho substitui o Cabeçalho dele, não vira um Cabeçalho 2 ao lado), qualquer que seja o Atualizar existentes; um que ele não tem é acrescentado. Os blocos de navegação deles apontam para as navegações importadas (exporte-as na linha Menus: as navegações dos modelos vêm sugeridas), as imagens para os anexos importados, e os links para o site de origem para o outro site.

  • Os widgets escolhidos vão para o fim da mesma barra lateral, ao lado dos widgets do próprio outro site (para Widgets inativos quando o tema dele não tem essa barra), cada um com um número livre. Importar o mesmo arquivo de novo com Atualizar existentes os atualiza no lugar em vez de acrescentá-los duas vezes. Um widget de menu de navegação aponta para o menu importado (exporte-o na linha Menus), um widget de imagem para a imagem importada, e as imagens e os endereços nos widgets de bloco para os importados.

Pelo WP-CLI e pela habilidade

wp eizport export --types=page --appearance=theme_mods:custom_logo+background_color,custom_css,widgets:text-3
wp eizport export --appearance=all --css-mode=start --no-css-markers
wp eizport export --types=page --menus=all --appearance=template_parts:header,templates:page
wp eizport import entrega.wxrz --css-mode=replace

Uma linha sozinha leva tudo dela; a chave de uma regra CSS (r:…) vem do eizport/get-export-options, que lista os itens de cada linha. A habilidade eizport/export recebe appearance (linha → "all" ou chaves), css_mode e css_markers.

Limites

  • A aparência vai para o tema ativo do outro site. Exportados de um tema e importados com outro, os theme mods só fazem sentido se esse tema usa as mesmas configurações.
  • Modelos e partes de modelo pertencem ao tema deles: importados num site com outro tema ativo, ficam guardados, sem uso, até esse tema ser ativado.
  • As fontes instaladas pela Biblioteca de fontes não são exportadas: os estilos que as usam caem nas fontes do outro site.
  • Os theme mods não vêm mais com o grupo Básicas da linha Opções: marque Theme mods do Personalizador. O logo do site de um tema de blocos é uma opção, em Básicas.
